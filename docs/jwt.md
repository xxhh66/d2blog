JWT（JSON Web Token）是一种在各方之间安全传输信息的开放标准，它就像一个电子身份证，包含了持有人的身份信息、权限和有效期限，并且经过数字签名，无法被伪造和篡改。

它的核心作用是解决用户身份认证问题。用户登录后，服务器会签发一个JWT给客户端，客户端在后续请求中带上它，服务器就能识别用户身份，从而省去了传统Session机制中服务端需要存储会话状态的开销。

### JWT的结构：三段式信息组合

一个JWT由三部分组成，用点`.`分隔，形如：`xxxxx.yyyyy.zzzzz`。

1. **头部 (Header)**：元数据区
   这部分是一个JSON对象，通常包含两个字段：`alg`（签名算法，如HS256或RS256）和`typ`（令牌类型，固定为`JWT`）。它就像信封上写的“加密方式”。

   json

   ```
   {
     "alg": "HS256",
     "typ": "JWT"
   }
   ```

   

2. **载荷 (Payload)**：数据区
   这部分包含了实际需要传递的数据，这些数据称为`声明 (Claims)`。它包含三类：

   - **注册声明 (Registered Claims)**：一组预定义的推荐字段，例如：
     - `iss` (Issuer)：签发者
     - `sub` (Subject)：面向用户
     - `aud` (Audience)：接收方
     - `exp` (Expiration Time)：过期时间（重要，确保令牌时效性）
     - `iat` (Issued At)：签发时间
   - **公共声明 (Public Claims)**：可自定义，为避免冲突，建议使用URI形式命名。
   - **私有声明 (Private Claims)**：通信双方自定义的字段，用于交换特定信息，如`user_id`、`role`等。

   json

   ```
   {
     "user_id": 1001,
     "role": "admin",
     "exp": 1735689600
   }
   ```

   

3. **签名 (Signature)**：防伪标识
   这是最关键的部分。服务器将编码后的头部和载荷拼接，再使用头部指定的算法和一个**只有服务器知道的密钥（Secret）** 进行签名。任何对头部或载荷的篡改都会导致签名验证失败，从而保证了令牌的**完整性**和**真实性**。

   **签名生成公式**：`signature = algorithm(base64(header) + "." + base64(payload), secret)`

###  JWT在认证流程中的角色

1. **登录，获取令牌**：用户通过用户名/密码登录，服务器验证通过后，创建一个包含用户身份信息的JWT，并签名后返回给客户端。
2. **请求，携带令牌**：客户端将JWT存储在本地（如localStorage）。之后每次请求，都将JWT放在HTTP请求的`Authorization`头中发送。例如：`Authorization: Bearer <你的JWT令牌>`。
3. **验证，处理请求**：服务器接收到请求，提取JWT，使用密钥验证其签名。验证通过，即可从载荷中读取用户信息，处理业务逻辑，而无需再查询数据库或维护会话状态。

### 核心优势与适用场景

JWT在微服务和前后端分离架构中非常流行，主要得益于以下优势：

- **无状态 (Stateless)**：服务器不保存任何会话信息，易于水平扩展。
- **自包含 (Self-contained)**：用户信息直接编码在令牌中，减少数据库查询。
- **跨域支持 (Cross-domain)**：不依赖Cookie，天然支持跨域请求。
